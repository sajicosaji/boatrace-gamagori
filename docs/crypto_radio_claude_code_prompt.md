# 実装依頼：仮想通貨ラジオ用「ソース素材パック」自動生成ツール

> この文書は Claude Code への実装依頼書です。最後まで読んでから、「8. 実装の進め方」に従って Phase 0 から着手してください。
> 外部サービスの情報は 2026-09-30 時点の調査結果です。実装時に各公式ドキュメントで最新の仕様を必ず確認してください。

## 0. 背景

- Gemini Notebook（2026年7月に NotebookLM から名称変更。機能は同じ）の「音声概要（Audio Overview）」で、日本語の仮想通貨ラジオを作っている。
- 現在の番組は2本。「時価総額TOP100ラジオ」と「今日の仮想通貨ラジオ」。
- 音声の出来はソースの質で決まる。いまは素材集めが手作業で、情報の角度も偏りがち。
- そこで、**複数の角度から情報を集め、Gemini Notebook に入れるだけで良い番組になる「ソース素材パック」を番組ごとに自動生成するツール**を作る。
- 実行環境は Windows PC。別に使っているボートレース予想ツールと同じく、Python を `.bat` のダブルクリックで動かす。
- （任意記入）現在の2番組の作り方：＿＿＿＿
  - 空欄の場合は「手作業でWebページやメモをソースに貼っている」と仮定してよい。

## 1. ゴールと非ゴール

### ゴール
1. 番組ごとに、Gemini Notebook にそのままアップロードできる素材一式（Markdownファイル群、URLリスト、音声概要のカスタマイズ用指示文、公開前チェックリスト）を1コマンドで生成する。
2. 情報を**多角的に**集める（4章の9つの角度）。1つの角度や1つの媒体に偏らせない。
3. 数値を正確にする（複数ソースでの照合、取得時刻の明記、取得失敗の明示）。

### 非ゴール（やらないこと）
- Gemini Notebook へのアップロードや音声生成の自動化。一般向けの公開APIがないため（Enterprise版のAPIは対象外）。Phase 4 で Google ドキュメント出力（Drive自動同期の利用）は任意で検討する。
- LLM API を使った要約や原稿の生成。要約は Gemini Notebook が行うので、このツールは事実とデータを整える役に徹する。
- 売買シグナル、価格予想、投資判断の提示。
- 有料APIを前提にした設計。無料で動くことを最優先にする（有料キーがあれば使える拡張ポイントは残してよい）。

## 2. 成果物

### 2.1 リポジトリ構成（目安。より良い構成があれば変えてよい）
```
crypto-radio/
├─ cryptoradio/               # Python パッケージ
│  ├─ __main__.py             # CLI エントリ
│  ├─ collectors/             # データ取得（ソースごとに1モジュール）
│  ├─ programs/               # 番組ごとの組み立て
│  ├─ render/                 # Markdown・指示文・チェックリスト生成
│  ├─ http.py / cache.py      # リトライ、レート制御、キャッシュ
│  └─ config.py
├─ config.yaml                # 番組設定、RSS一覧、閾値、ウォッチリスト
├─ data/
│  ├─ events.yaml             # 手動管理の予定（アンロック、アップグレード等）
│  ├─ domestic_listings.csv   # 国内取引所の取扱銘柄（半手動）
│  └─ snapshots/              # 前回比計算と取り上げ履歴
├─ knowledge/
│  ├─ japan_regulation.md     # 日本の規制・税制の確定情報（出典と最終確認日つき）
│  └─ security_basics.md      # セキュリティの基本対策（固定テキスト）
├─ output/YYYY-MM-DD/<program>/   # 生成物（git管理外）
├─ tests/                     # fixtures/ に実レスポンスを保存
├─ .env.example
├─ requirements.txt
├─ 1_今日のラジオ素材.bat など
└─ 使い方.txt
```

### 2.2 1回の実行で出力するもの（例：`output/2026-09-30/daily/`）
| ファイル | 内容 |
|---|---|
| `00_使い方.md` | この素材で音声概要を作る手順（アップロードするファイル、URLの追加、推奨形式、指示文の貼り付け場所） |
| `01_*.md` 〜 `0N_*.md` | ソース本体。角度ごとにファイルを分ける（例：`01_相場概況.md`、`02_デリバティブとセンチメント.md`、`03_ニュース_海外.md`、`04_ニュース_国内.md`、`05_今後の予定.md`） |
| `urls.txt` | Gemini Notebook に Webソースとして追加するURL（記事、一次情報、ETFフロー表など）。1行1URL、各URLの上に `#` で一言説明 |
| `customize_prompt.txt` | 音声概要の「カスタマイズ」欄に貼る指示文。先頭に推奨形式（Deep Dive / Brief / Critique / Debate）を書く |
| `checklist.md` | 公開前の確認用。主要数値の一覧（照合結果つき）、警告、取得に失敗したソース |
| `raw/` | 取得した生データ（JSON）。デバッグ用 |

制約：ソースファイルは1番組あたり15ファイル以下、1ファイル2万字以下にする。Gemini Notebook の無料版は1ノートブック50ソース、1ソース50万語までなので、余裕を持たせる。

## 3. 番組一覧と仕様

### P1 `top100` 時価総額TOP100ラジオ【既存を強化】Phase 1
- 頻度：毎日〜週数回
- 必須データ
  - TOP100の価格（USD・円）、24時間/7日/30日の変化率、時価総額、出来高、過去最高値（ATH）からの下落率
  - 前回スナップショットとの順位変動、TOP100への新規ランクインと圏外落ち
  - 7日間の上昇・下落上位10（ステーブルコインとラップトークンは除外）
  - BTC・ETHのドミナンス、暗号資産全体の時価総額
  - 各銘柄の国内取引所での取扱有無、所属カテゴリ
- 並べ方：「話す価値の高い順」にする。100銘柄を均等に並べない。全銘柄の表は末尾に付録として置く。
- 推奨形式：Deep Dive

### P2 `daily` 今日の仮想通貨ラジオ【既存を強化】Phase 1
- 頻度：毎朝
- 必須データ
  - 主要銘柄（BTC、ETH、`config.yaml` のウォッチリスト）の価格と変化率（USD・円）
  - 国内取引所の円建て価格と、海外価格との乖離
  - 恐怖強欲指数（当日値と7日・30日の推移）
  - デリバティブ：資金調達率と建玉（2取引所以上）
  - 直近24時間のニュース（海外と国内。同じ話題はまとめて、報道した媒体数を付ける）
  - トレンド銘柄
  - 今日・明日の予定（経済指標、FOMC、アンロックなど）
- 推奨形式：Deep Dive。短縮版として Brief 用の指示文も同時に出力する。

### P3 `weekly` 週刊まとめ＋来週の予定【新規】Phase 2
- 頻度：週末
- 必須データ：7日間の値動きのまとめ、週のニュース上位（報道媒体数の順）、カテゴリ別の週間騰落、恐怖強欲指数の推移、ステーブルコイン供給量の週次変化、上場企業の保有動向、**来週の予定（日付とJSTの時刻つき）**
- ETFフローはURLを `urls.txt` に入れる（4章E）
- 推奨形式：Deep Dive

### P4 `deepdive --coin <CoinGecko ID>` 今週の1銘柄深掘り【新規】Phase 2
- 必須データ：概要と公式リンク、1年間の価格推移、ATH、供給量（流通・総量・上限）、FDV/時価総額比（将来の売り圧の目安）、カテゴリと同じカテゴリの競合上位、DefiLlama の TVL と手数料（該当する場合）、その銘柄に関する直近ニュース、国内取扱の有無、予定されているイベント
- 「リスク確認項目」セクションをテンプレートで必ず出す。項目は供給インフレ、保有の集中、規制、技術・セキュリティ、競合。項目ごとに取得できた事実を入れ、無ければ「データなし」と書く。
- 公式サイト、ホワイトペーパー、ドキュメントのURLを `urls.txt` に入れる
- `suggest deepdive`：候補を5つ提案する（TOP100内の7日変動上位、トレンド入り、過去8週に取り上げていないもの）。取り上げた履歴は `data/snapshots/` に記録する
- 推奨形式：Deep Dive（別バージョンとして Critique）

### P5 `japan` 日本の規制・税制・取引所【新規】Phase 2
- 必須データ：金融庁の新着情報（RSSを暗号資産関連のキーワードで絞る）、JVCEA の新規取扱・取扱廃止のお知らせ、国内メディアのニュース、`knowledge/japan_regulation.md` の内容、国内価格の乖離
- `japan_regulation.md` の最終確認日が30日以上前なら、`checklist.md` に警告を出す
- 推奨形式：Deep Dive

### P6 `sectors` テーマ別の資金の流れ【新規】Phase 3
- CoinGecko のカテゴリ別データ（時価総額の変化、上位銘柄）、スナップショットから計算した7日変化、DefiLlama のチェーン別TVLの変化、テーマ別のニュース
- 対象テーマ（AI、RWA、ステーブルコイン、L2、ミーム、DePIN、DeFi など）は `config.yaml` で設定できるようにする

### P7 `thermometer` 市場の温度計【新規】Phase 3
- 恐怖強欲指数（30日）、資金調達率と建玉（複数取引所）、BTCネットワーク（手数料、ハッシュレート、難易度調整）、ステーブルコイン供給量の7日/30日変化、上場企業の保有、予測市場（Polymarket）の暗号資産関連の確率
- 各指標に「過去30日の中でどの位置か（パーセンタイル）」を付けて文脈化する

### P8 `security` セキュリティ・詐欺注意報【新規】Phase 3
- ニュースRSSから、ハッキング・流出・詐欺関連の記事をキーワードで抽出する（英語と日本語）。金融庁の無登録業者への警告も含める
- 「リスナーが取るべき基本対策」は `knowledge/security_basics.md` の固定テキストとして同梱する

### P9 `debate --topic "<テーマ>"` 強気 vs 弱気【新規】Phase 3
- テーマのキーワードで記事を集め、強気寄りと弱気寄りの両方のURLを `urls.txt` に入れる。分類はタイトルと要約のキーワードによる簡易判定でよいが、判定の根拠も出力する
- 関連する客観データ（価格、指標）を添える
- 推奨形式：Debate

### ツール化しないもの
「今さら聞けない基礎講座」と「過去のサイクルとの比較」は手作業で作る。ただし過去サイクルの比較に使えるよう、`deepdive` と `weekly` にはATHと1年推移を含める。

## 4. 多角的な情報取得：データソース

### 原則
- **角度を下の A〜I の9つに分け、各番組は最低4つの角度から情報を入れる。**
- **同じ事実は、できるだけ2つ以上のソースで照合する。**
- **海外メディアと国内メディア、一次情報（公式発表や当局）と報道の両方を入れる。**
- 下の表は調査時点の候補。実装時に `doctor` コマンドで到達性とレスポンス形式を実際に確かめ、使えないものはフォールバックに切り替える。

### A. 価格・時価総額
| ソース | 用途 | キー | 備考 |
|---|---|---|---|
| CoinGecko API（Demoプラン） | `/coins/markets`、`/global`、`/coins/{id}`、`/coins/{id}/market_chart`、`/coins/categories`、`/search/trending`、`/exchange_rates` | 無料のDemoキー（`x-cg-demo-api-key` ヘッダ） | 100回/分、月1万回まで。出典の表記が必要。キーなしの Keyless Public API もあるが、制限がより厳しい |
| CoinPaprika または CoinMarketCap（Basic） | 価格照合用の第2ソース | CoinPaprika は不要（要確認）、CoinMarketCap は無料キー | 主要銘柄で1%以上ずれたら警告 |

- 月1万回を超えないよう、キャッシュ（同じリクエストは10分間再利用）を入れ、1回の実行での CoinGecko 呼び出しを20回程度に抑える。
- 円建て価格は、`vs_currency=jpy` の追加呼び出しと `/exchange_rates` での換算のうち、効率の良い方でよい。
- 番組を収益化する場合は、Demoプランの利用条件を確認すること。Demoは出典表記が条件で、商用利用には有料プランが必要とされている。

### B. 国内市場
| ソース | 用途 | キー |
|---|---|---|
| bitFlyer / Coincheck / bitbank の公開API | 円建て価格、海外価格との乖離 | 不要 |
| JVCEA（日本暗号資産等取引業協会）のグリーンリスト、新規取扱・取扱廃止のお知らせ | 国内で買える銘柄の把握 | 不要（Webページ） |

国内の取扱一覧にはAPIがないため、`data/domestic_listings.csv` を用意する。取引所の公開APIの通貨ペア一覧から自動更新できる部分は自動化し、それ以外は手動更新として `使い方.txt` に手順を書く。

### C. デリバティブ
| ソース | エンドポイント例 | キー |
|---|---|---|
| OKX 公開API | `/api/v5/public/funding-rate`、`/api/v5/public/open-interest` | 不要 |
| Binance USDⓈ-M 公開API | `/fapi/v1/premiumIndex`、`/fapi/v1/openInterest` | 不要（米国IPなどからは HTTP 451 で拒否されることがある） |
| Hyperliquid | `POST https://api.hyperliquid.xyz/info`（`{"type": "metaAndAssetCtxs"}`） | 不要 |

- Bybit は日本居住者向けサービスを終了しているため、既定では使わない。
- Coinglass は有料なので使わない。
- 取引所ごとの値を並べて表示し、単純平均だけにしない。
- 市場データとして参照するだけにする。番組で無登録の海外業者の利用を勧める表現はしない（7章）。

### D. オンチェーン・DeFi
| ソース | エンドポイント例 | キー |
|---|---|---|
| DefiLlama 無料API | `api.llama.fi/v2/chains`、`/protocols`、`/protocol/{slug}`、`/overview/fees`、`/overview/dexs`、`stablecoins.llama.fi/stablecoins` | 不要 |
| mempool.space | 手数料、ハッシュレート、難易度調整 | 不要 |

DefiLlama のアンロック（Emissions）、Yields、Hacks は有料の Pro 限定なので使わない。

### E. 資金フロー
- 現物ETFのフロー：Farside（farside.co.uk）にはAPIがない。スクレイピングはせず、該当ページのURLを `urls.txt` に入れて Gemini Notebook に直接読ませる。
- ステーブルコインの供給量：DefiLlama。
- 上場企業の保有：CoinGecko の `/companies/public_treasury/{bitcoin|ethereum}`。

### F. センチメント・注目度
- alternative.me の恐怖強欲指数：`https://api.alternative.me/fng/?limit=30`（キー不要。出典の表記が必要）。
- CoinGecko の `/search/trending` と `/coins/categories`。
- Polymarket Gamma API（`https://gamma-api.polymarket.com/events` など。キー不要）：暗号資産や金融政策に関する市場が織り込んでいる確率。**確率データとしてのみ扱い、賭けを勧めない。** 日本から届くかは `doctor` で確認する。

### G. ニュース（RSS）
- 海外
  - CoinDesk `https://www.coindesk.com/arc/outboundfeeds/rss/`
  - The Block `https://www.theblock.co/rss.xml`
  - Cointelegraph `https://cointelegraph.com/rss`
  - Decrypt `https://decrypt.co/feed`
  - The Defiant `https://thedefiant.io/feed/`
- 国内：CoinPost、CoinDesk JAPAN、あたらしい経済、NADA NEWS など。フィードURLは実装時に各サイトで特定・検証してから `config.yaml` に登録する（未検証のURLを決め打ちしない）。
- 一次情報：金融庁の新着情報RSS（URLは `https://www.fsa.go.jp/kouhou/rss.html` に掲載）、JVCEA の新着情報。
- 使わないもの：CryptoPanic API（無料プランは2026年4月に終了）。
- 処理
  - 期間で絞る（daily は24時間、weekly は7日）。
  - 同じ話題はタイトルの類似度でまとめ、報道した媒体の数を重要度の目安にする。
  - **記事本文は転載しない。** 見出し、RSSの要約、URLだけをソースに入れる。本文を読ませたい記事は `urls.txt` に入れる。
  - 主要な話題には、できれば論調の異なる記事を並べる。

### H. マクロ・予定
- 予定は `data/events.yaml`（手動管理）に集約する：FOMC、米CPI、雇用統計、日銀の金融政策決定会合、トークンアンロック、ネットワークアップグレード、ETFの判断期限など。
- 公式日程の参照先
  - FOMC：`https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm`（2026年の残りは 10/27-28 と 12/8-9）
  - 米CPI：`https://www.bls.gov/schedule/news_release/cpi.htm`
- 初期データとして、2026年10月〜12月分を公式ページで確認して投入する。
- アンロックには無料APIがないため手動で入力する（Tokenomist などのページを見て入力）。`events.yaml` の書き方と例を `使い方.txt` に書く。
- 米国時間の予定は必ずJSTに変換して表示する。

### I. 日本の規制・税制（`knowledge/japan_regulation.md` に確定情報として書く）
調査時点（2026-09-30）で確認した事実は下記のとおり。ファイルには各項目の出典URLと最終確認日を書く。
- 金融商品取引法と資金決済法の改正法が2026年7月15日に成立し、7月23日に公布された。暗号資産の規制は資金決済法から金商法に移る。施行日は、2027年7月22日までの政令で定める日。
- 改正後は、暗号資産を対象にした投資助言業にも金商法の規制がかかる。インサイダー取引規制も導入される。
- 税制：令和8年度税制改正で、「特定暗号資産」の譲渡益などに20.315%の申告分離課税と、損失の3年間の繰越控除が導入された。適用は改正金商法の施行日の翌年1月1日以後で、2028年1月からが有力とされている（施行日次第のため、推測を含む）。海外取引所やDEXでの取引などは対象外で、総合課税のまま。

## 5. 出力フォーマット

### 5.1 ソースMarkdownの共通ルール
- 冒頭に書くもの：番組名、**データ基準時刻（JST）**、使用した出典の一覧。
- 数値の書き方
  - 金額はUSDと円を併記する（例：`$63,210（約940万円）`）。
  - 大きな数は日本語の単位も併記する（例：`時価総額 3.2兆ドル（約480兆円）`）。音声で読み上げやすくするため。
  - 変化率には符号を付ける（`+3.2%` / `-1.5%`）。
  - 計算で出せる文脈を付ける（「過去30日で最大の下落」「ATHから-18%」など）。
- 事実とデータ（出典つき）に徹する。「なぜ動いたか」はニュースの見出しと要約を並べて示し、ツール側で因果を断定しない。
- 取得できなかった項目は `データなし（理由：タイムアウト など）` と書き、推測値で埋めない。

### 5.2 customize_prompt.txt のテンプレート（番組ごとに調整する）
```
【推奨形式】Deep Dive
対象：仮想通貨を保有している日本の会社員（初級〜中級）。通勤中に聴く。
冒頭：この放送が〔YYYY年M月D日 H時〕時点の情報であることを最初に伝え、今日の要点を3つ述べる。
構成：①要点3つ ②値動きとその背景（ニュースとの関係）③保有者にとっての意味 ④今後の予定（日付つき）⑤注意点。
話し方：価格は円とドルで伝える。変化率は7日・30日の流れや過去最高値との比較で文脈を付ける。専門用語には一言の説明を添える。
バランス：強気と弱気の両方の見方を紹介する。特定銘柄の売買推奨や価格予想はしない。
締め：「投資判断はご自身で」と一言添える。
```
- 指示文は長くしすぎない（目安500字以内）。
- 調査時点の情報：音声概要の長さ設定（短め/標準/長め）は英語だけで、日本語は標準の長さになるという報告がある。長さはソースの量と指示文で調整する前提にする。

### 5.3 checklist.md
- 主要数値の表（値、出典、第2ソースとの差、判定）
- 警告の一覧（ソース間の乖離、古いナレッジ、スナップショットの欠損など）
- 取得に失敗したソースとその理由
- 公開前に人が確認する項目（固定）
- 禁止表現チェックの結果（7章）

## 6. 技術要件

- Python 3.11以上。依存は最小限にする（httpx か requests、feedparser、PyYAML、python-dotenv、pytest 程度）。
- CLI
  - `python -m cryptoradio run <program> [--date YYYY-MM-DD] [--coin ID] [--topic TEXT] [--offline]`
  - `python -m cryptoradio suggest deepdive`
  - `python -m cryptoradio doctor`（全ソースについて、到達性、キーの設定、レスポンス形式を確認して表で出す）
- 部分成功：1つのソースが失敗しても全体を止めない。失敗は `checklist.md` とログに残す。
- HTTP：タイムアウト、指数バックオフのリトライ（最大3回）、ソースごとのレート制御、User-Agent の設定。
- キャッシュ：`.cache/` にレスポンスを保存し、有効期限をソースごとに設定する。
- 設定：APIキーは `.env`（`COINGECKO_DEMO_API_KEY` など）に置き、`.env.example` を用意する。`.env`、`output/`、`.cache/` は `.gitignore` に入れる。
- 時刻の表示はすべて `Asia/Tokyo`（内部はUTCでよい）。
- Windows対応
  - Python側のファイル読み書きは `encoding="utf-8"` を明示し、標準出力もUTF-8にする。
  - `.bat` は CP932（Shift_JIS）・CRLF で保存する。UTF-8で保存すると日本語が文字化けする。`@echo off` と `cd /d "%~dp0"` で始め、最後に `pause` を置く。
  - `.bat` の例：`1_今日のラジオ素材.bat`、`2_TOP100素材.bat`、`3_週刊素材.bat`、`4_銘柄深掘り素材.bat`（銘柄IDを入力させる）、`9_接続チェック.bat`。
  - 生成が終わったら、出力フォルダをエクスプローラーで開く。
- テスト：`tests/fixtures/` に実際のレスポンスを保存し、ネットワークなしで整形ロジックを検証する。`--offline` を付けると fixtures から素材を生成できるようにする。
- 出典の表記：CoinGecko、alternative.me など表記が必要なソースは、ソースファイルの冒頭と `00_使い方.md` に書く。

## 7. 内容に関するルール（必須）

1. 売買推奨、価格予想、「今が買い」などの表現を出力に含めない。カスタマイズ用の指示文でも禁止を明示する。
   - 理由：2026年7月に成立した改正金商法が施行されると、暗号資産の投資助言にも金商法の規制がかかる。今のうちから推奨をしない設計にしておく。
   - 生成物を禁止語リスト（例：「買い時」「爆上げ」「確実に上がる」「今すぐ買う」「仕込み時」）で検査し、見つかれば `checklist.md` に警告を出す。リストは `config.yaml` で編集できるようにする。
2. 無登録の海外取引所の利用を勧める表現をしない。海外取引所のデータは市場の指標として引用するだけにする。
3. 予測市場のデータは確率としてのみ扱い、賭けを勧めない。
4. 記事本文を転載しない（見出し、要約、URLだけにする）。
5. 各APIの利用規約や robots.txt に反する取得をしない。スクレイピングが必要な情報はURL渡しにする。
6. 取得に失敗した値や不確かな数値を推測で埋めない。
